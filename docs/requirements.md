# 要件定義

## 1. 背景

本プロジェクトの目的は、Codex から Blender を操作可能にし、モデリング支援、Blender 内 UI、外部 AI サービス連携を一体で扱える MCP ベースの連携基盤を構築することです。

## 2. 目的

- Codex から Blender に対して安全かつ再現可能な操作指示を送れるようにする
- Blender 側で実行結果を可視化し、必要に応じてユーザー承認を介在できるようにする
- Blender 内 UI から Codex と対話し、操作履歴や生成結果を確認できるようにする
- 外部 AI サービスを差し替え可能な構成で統合する

## 3. スコープ

### 3.1 対象

- Blender アドオンの開発
- MCP サーバーの開発
- Blender と MCP サーバー間の通信
- Blender 内 UI の開発
- 外部 AI サービス接続レイヤーの開発
- ローカル開発環境、テスト、リリース手順の整備

### 3.2 非対象

- 初期段階での完全自律モデリング
- 商用 SaaS との包括的な課金管理
- 複数 DCC ツール同時対応
- クラウド常駐の大規模分散実行基盤
- 不特定多数利用を前提とした公開サーバー運用

## 3.3 MVP 境界

MVP では「Codex から Blender を安全に接続し、限定された構造化操作を実行できること」を成立条件とする。

### MVP で対象に含める

- Blender 起動状態と接続状態の確認
- プリミティブ生成
- 既存オブジェクトの基本変形
- シーン内オブジェクト一覧取得
- オブジェクト削除の承認付き実行
- Blender UI での接続状態、実行履歴、入力表示、承認待ち表示
- チャット形式履歴表示
- 複数タブ UI
- ローカル限定接続
- 監査ログの最小保存

### MVP では対象外とする

- 複雑なメッシュ編集の自動化
- ノードベースの高度なマテリアル生成
- アニメーション、リギング、物理設定の自動生成
- 破壊的操作の自動実行
- 公開ネットワーク越しの制御
- 完全自律の AI モデリング実行

## 4. 想定ユーザー

- Blender を使う個人開発者
- Codex から 3D ワークフローを実行したい技術者
- Blender と生成 AI の統合基盤を検証したい研究開発用途

## 5. ユースケース

### UC-01 Codex から Blender へ操作指示を送る

- ユーザーは Codex から `primitive_cube_add` や `bevel` のような構造化操作を実行できる
- 結果は Blender シーンに反映される
- 実行ログは追跡できる

### UC-02 Blender 側 UI から Codex に依頼する

- ユーザーは Blender のサイドパネルまたは専用ウィンドウから自然言語で指示を送れる
- 応答、提案操作、エラー内容を UI 上で確認できる

### UC-03 外部 AI サービスにプロンプトまたはコンテキストを送る

- Blender シーン情報や選択オブジェクト情報を外部 AI サービスへ送れる
- 応答を操作候補または注釈として Blender へ戻せる

### UC-04 危険操作の承認

- オブジェクト削除、モディファイア適用、上書き保存などの操作は承認フローを通せる

### UC-05 シーン情報を安全に要約して AI へ渡す

- ユーザーは選択オブジェクトやシーン概要を AI サービスへ渡せる
- AI には必要最小限の構造化情報のみを送る
- 初期段階ではシーン全体の重い解析は必須としない

## 6. 機能要件

### FR-01 MCP サーバー

- Codex から呼び出せる MCP ツールを提供する
- Blender 接続状態を返せる
- Blender へのコマンド送信と結果受信を行える
- 実行可能なツールは MVP の許可操作に限定できる

### FR-02 Blender アドオン

- Blender 内で常時接続状態を維持し、必要に応じて再接続できる
- Blender Python API を用いて対象操作を実行できる
- 実行結果、エラー、ログを返せる
- 実行中、成功、失敗の状態を UI へ反映できる

### FR-03 Blender UI

- 接続状態、履歴、リクエスト入力欄、実行結果を表示できる
- 実行前確認ダイアログを表示できる
- 承認待ち操作を区別して表示できる

### FR-04 AI サービス連携

- OpenAI 互換 API を最初の対象とする
- モデル呼び出し、タイムアウト、失敗時リトライを扱える
- ベンダー依存処理を抽象化する
- 初期段階では AI の応答を直接実行せず、操作候補または構造化提案として扱う

### FR-05 セキュリティ/安全性

- ローカル限定接続を初期前提とする
- 実行可能な操作種別を制限できる
- 監査ログを保存できる
- 破壊的操作は `preview -> confirm -> execute` を前提とする

## 7. 非機能要件

- Windows を初期対応環境とする
- Blender LTS 系を優先対応とする
- ローカル単体で開発/検証可能であること
- 障害時に Blender をクラッシュさせにくい設計であること
- AI 呼び出し失敗時に Blender UI が固まらないこと
- Blender 未起動時や接続断時に明示的なエラーを返せること
- ログにより失敗原因の一次切り分けができること

## 8. 実現可能性評価

### 8.1 実現性が高い

- Blender アドオンによる UI 表示
- Blender Python API を用いた標準操作の実行
- MCP サーバーからローカルプロセス/HTTP/WebSocket 経由で Blender と通信
- 外部 AI サービスとの API 接続

### 8.2 制約付きで実現可能

- 自然言語からの完全自動モデリング
  - 可能だが、操作候補生成と承認フローを前提にすべき
- Blender 実行中の双方向リアルタイム連携
  - 可能だが、Blender の UI スレッド制約に注意が必要
- 長時間処理や大型シーン解析
  - 可能だが、非同期化とタイムアウト設計が必要

### 8.3 初期段階で避けるべき領域

- 任意 Python コードの無制限実行
- ネットワーク越し公開を前提とした遠隔操作
- 承認なしの破壊的操作自動実行

## 9. 受け入れ基準

### Phase 1

- Codex から `blender_status` 相当の接続確認ができる
- `create_primitive` と `list_objects` が動作する
- 単一オブジェクトに対する基本変形が動作する
- オブジェクト削除が承認付きで動作する
- Blender UI に接続状態、チャット形式履歴、タブ UI、実行履歴、エラーが表示される
- Blender 未起動時に失敗が期待通り通知される

### Phase 2

- Blender UI から Codex へ依頼を送れる
- 外部 AI サービスから操作提案を受け取り確認できる
- 承認付き実行フローが動作する
- 許可操作と承認必須操作の境界が UI とログに反映される

### Phase 3

- シーン情報要約、選択情報連携、監査ログ保存が整う
- 検証手順とリリース手順がドキュメント化される

## 10. 現工程の結論

要件定義工程の現時点の結論は以下とする。

- MVP は「接続確認、限定操作、基本 UI、ローカル安全運用」に絞る
- 採用方針として、MVP 後すぐの機能拡張を見据えた前倒し構造を許容する
- AI は初期段階では提案生成までを主責務とし、自動実行主体にはしない
- 高度モデリング、公開運用、完全自律実行は後続工程へ送る
- 仕様検討では allowlist、データ契約、UI 状態遷移、安全境界、開発環境基線を重点論点とする
